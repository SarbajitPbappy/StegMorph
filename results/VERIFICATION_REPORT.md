## 2. Code review (exp4.py, exp5.py, stegmorph_recon.py, srm_lite.py)
OK:
- Cover i and stego i share a split (tr mask built per image); detectors fit only on train images; AUC on held-out; bootstrap resamples paired test images (index ordering consistent). No test-set tuning is visible in the code (hyperparameters fixed: LR C=0.05, HGB 150 iters depth 4). Whether C=0.05 was chosen earlier by looking at test results (E1-E3) cannot be verified from the code.
- GA and RAND both call the same `need` (total_bits) and `_repair`; embedded-bit overshoot is small. I measured on 25 seed-0 noise covers at 0.005 bpp (need=339 bits): capacity above need = 0.28 bits (GA) vs 0.96 bits (RAND). Matched in bits.
- Detector never receives the mask, the GA cost map, or payload. It is trained per (scheme, payload), i.e. it knows the scheme and rate (a strong, informed-steganalyst setting; fine, but state it).
Bugs / risks:
1. Hash-grouping is a no-op. Hashes are computed AFTER per-index noise (`default_rng(i)`), so identical files would hash differently; and in this clone I found 0 byte-identical files among 6400 anyway. The "exact-hash group split" is effectively an image-level random split. MRI slices from the same subject remain in both train and test (no subject IDs) -> absolute AUCs may be inflated for both schemes; GA-vs-RAND differences are probably less affected but this is untested. Notes say "25 duplicate files": I could not reproduce that count.
2. Confound in "position selection": at equal bits GA uses ~165 pairs (156 LSB-branch, 9 PVD) vs RAND ~143 pairs (110 LSB, 33 PVD). So GA is not just choosing different positions; it shifts the operator mix to 2-LSB replacement in smooth dark background and touches ~15% more pixels. The negative result is about an MSE-fitness GA that changes this mix, not about "optimised position selection" generally.
3. E5 control is vacuous: `("A_noise","A_noise", ntrT)` uses sub=304 but the A train split has only 280 pairs, so slicing [:304] changes nothing (the sub304 and full A->A numbers are identical in the JSON). The notes' claim that the training-size confound is controlled is therefore unsupported; A-train (280) is actually smaller than T-train (304), which cuts the other way, but the "control" was not performed.
4. Statistics: n_test = 120-180 pairs; CIs are bootstrap over test images only (ignores training-set variance); seeds draw from the same pool of 6400/253 images so they are not independent replicates; E5 "mean of 3 seeds, 90% CI from per-seed bootstrap SEs" is an approximation (assumes independence). TOST equivalence margin 0.02 is tight relative to a SE of ~0.015-0.03 per cell.
5. Detectors are weak/simplified (SRM-lite LR with ~3k features on ~300-420 training pairs; SPAM-686 + HGB). "Equivalent" can mean "both barely detected". No CNN, no ensemble classifier, no selection-channel-aware features (Denemark et al. 2014 show these help against adaptive embedding; a GA mask is deterministic from the cover, so such a detector could exploit it).
6. Extraction assert only on first 2-3 images; PSNR on first 150 images (E4) / 150 crops (E5 psnr).
7. T set: non-overlapping crops are grouped by source file, but near-duplicate/augmented images across files are not checked; tumor set provenance unknown (JPEG history).

Queries: (1) "does optimizing embedding locations with an evolutionary algorithm improve security against steganalysis compared with random embedding at equal payload" (SciSpace); (2) "particle swarm or genetic optimization of embedding positions evaluated against SRM or SPAM steganalysis versus random positions medical images" (Firecrawl research); (3) alphaXiv discover: metaheuristic pixel selection steganalysis medical; (4) "ablation of random versus optimized pixel selection in LSB steganography measured by SRM or CNN detector AUC on medical or MRI images" (SciSpace); (5) "is distortion-minimizing embedding in smooth regions more detectable than in textured regions" (SciSpace); (6) "Texture attention-guided adaptive LSB ... GA tuning ablation Xu-Net Ye-Net AUC" and (7) "Content-adaptive LSB ... ACO ablation CNN steganalysis" (Firecrawl research); (8) "Coati optimization ... SRM footprint ... random baseline" (SciSpace).
Closest papers:
- Aljughaiman & Alrawashdeh, Sci Rep 2026, "Optimization-driven steganographic system based on fused maps and blowfish encryption" (PSO selects embedding priority map; PMC12873396, doi 10.1038/s41598-026-35556-9). Partially read (full-text passages via Firecrawl). Tests: BOSSbase covers, 0.1-1.0 bpp, Xu-Net/Ye-Net/RS, "with PSO" vs "without PSO" Ye-Net AUC tables (both ~0.5 on only 20 cover/20 stego test images; 160 training pairs; Ye-Net predicts all "cover"). Does NOT test: random-position baseline at matched payload with a competent detector; medical/MRI; feature (SRM/SPAM) detectors; any power analysis. Closest in design but too underpowered to show anything.
- Aljughaiman & Alrawashdeh, Sci Rep 2025, "Content-adaptive LSB steganography with saliency fusion, ACO dispersion ... with ablation study" (PMC12852717, doi 10.1038/s41598-025-33920-9). Partially read. Tests: ACO vs random vs perm vs saliency_topk index modes at matched payload, but compared on PSNR/SSIM (differences <0.5 dB); security reported as "random-level detectability" for the ACO scheme against CNN steganalyzers. Does NOT test: security of ACO vs random head-to-head with a working detector; MRI; feature detectors.
- Schottle & Bohme, IEEE TIFS 2016, "Game Theory and Adaptive Steganography" (doi 10.1109/TIFS.2015.2509941; scispace.com/papers/game-theory-and-adaptive-steganography-1dp1lcejhb). Abstract only (paywalled) - NOT read in full. Theory: naive adaptive embedding beats random only if the adaptivity criterion is not recoverable by the warden; optimum lies between adaptive and random uniform. Directly relevant to explaining why a deterministic cost-driven GA mask can be MORE detectable than random. No GA, no medical data.
- Havard et al., arXiv 2304.12503 (CNN-assisted S-UNIWARD). Read in full. Optimises S-UNIWARD parameters against Yedroudj-Net; baseline is default S-UNIWARD, not random position selection; BOSSbase/ImageNet; not medical. Notable: its optimiser pushed embedding toward smooth areas and fooled that CNN, i.e. opposite direction from your finding, but it trains against the detector, which your GA does not.
- Not read (abstract level only): Coati-optimisation SRM-footprint steganography (scispace.com/papers/coati-optimization-algorithm-driven-content-adaptive-bs04aydfca83); Ambika & Biradar, EH-MB optimal pixel selection for medical images (scispace.com/papers/secure-medical-image-steganography-through-optimal-pixel-1toxuf85up); Vazquez et al., GA medical-image steganography, Front Robot AI 2022 (PMC9582659; PSNR only, no steganalysis in abstract); Alrawashdeh et al. 2026 texture-attention + optional GA ablation (scispace.com/papers/texture-attention-guided-adaptive-lsb-steganography-with-u-77ognbuuz2eh); Denemark et al. 2014 selection-channel-aware SRM (relevant to detector choice).
Finding: I did not find a paper that compares a GA/metaheuristic position selector against random selection at matched payload under SRM/SPAM-type or properly powered CNN steganalysis on MRI. Nearest hits compare against random only on PSNR, or use tiny CNN test sets. Search coverage is limited to these indexes and abstracts for many hits.

## 4. Verdict on C1-neg: PARTIAL (not ESTABLISHED, not clean OPEN)
Gap plausibly open for the exact setting (MRI, feature detectors, matched payload), but the underlying principle (non-uniform, deterministic, cost-driven adaptive embedding can be easier to detect than uniform random if the warden exploits it; Schottle-Bohme 2012/2016) is known, and my search was not exhaustive (several full texts unavailable).
Overstatements in the draft:
1. "no security benefit" fine for GA, but headline wording "GA-selected ... LSB/PVD scheme" generalises from ONE reconstruction with an MSE fitness and a changed branch mix; the original StegMorph/other fitnesses untested.
2. "detectability is equivalent on one MRI source": equivalence holds only for detector A on T_raw (and CI-based on a 3-seed average of dependent seeds); detector B is inconclusive at 0.005/0.01 (90% CI upper +0.027/+0.033, beyond margin). Seed 0 alone: T_raw B diffs -0.018/-0.001/-0.008 with 95% CIs spanning +-0.04.
3. "higher on another" rests on Alzheimer + synthetic Gaussian noise (sigma 1.5) covers, which the same notes call synthetic; E5 T_noise shows a mixed picture (A equivalent, B GA worse at 0.005/0.01). Strongest effect lives only in the synthetic setting.
4. "PSNR 3-7 dB higher": 3 dB is T_raw seed 0 on 150 crops; 7 dB is the noise-augmented set.
5. "against SRM-lite+LR and SPAM+gradient-boosting" - these are simplified stand-ins (not SRM/maxSRM, no ensemble classifier, no CNN); wording "feature detectors" should say "simplified".
6. Training-size control claimed in RESULTS_E5 is not actually executed (see risk 3).
7. Split described as exact-hash/group: effectively random image-level (risk 1). Leakage between slices of the same subject unquantified.
8. Payload scale: 0.005-0.02 raw bpp = 0.015-0.06 embedded bpp (triplication), already noted; results do not extend to higher payloads (AUC saturates to 1.0 on raw Alzheimer).
9. Gate: "15 queries" and "no paper found" claim is OK as a statement of what was found, but not a proof of absence; keep PARTIAL.
