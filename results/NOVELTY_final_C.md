## 1. MOLSBM (IST 2024) - two PDFs
Files: `MOLSBM_A_..._Method.pdf` and `... (1).pdf`: byte hashes differ but extracted text is identical except the IEEE download timestamp. One paper, counted once.
- Title: "MOLSBM: A Multi-Objective LSB Matching Steganography Method". Authors: Vajiheh Sabeti, Sepideh Faiazi (Alzahra Univ., Tehran). Venue: 2024 11th International Symposium on Telecommunications (IST), IEEE, pp. 738-743 (per ISeCure ref [51]; page footers garbled). DOI 10.1109/IST64061.2024.10843581 (p1). 6 PDF pages.
- Optimiser: NSGA-II, population 20, pc 0.7, pm 0.1, 20 iterations (p4). Per block, chromosome = 8-bit seed (for rng/randperm pixel path) + one +1/-1 gene per embedded bit (p3). Selected: seed (order/path) and pattern (direction). Final pick from Pareto front by LINMAP distance (p4).
- Objectives: F1 = number of mismatched LSBs, i.e. number of modifications. Quote (p3): "minimize the number of pixel modifications needed to match the message bits with the LSBs". F2 = block histogram L1 difference cover vs stego (p3). Yes, one objective IS the modification count.
- Data: NRCS, "around 2,000 images", "1,000 images used for testing" (p4); security uses "500 images from NRCS" (p5). Block-size study: Lena, Baboon only (Table III, p5). Payload: random bits, 0.3/0.5/0.8 bpp.
- Steganalysers: ker1, ker2 (Ker 2005), CNGL, ALE. Table IV (p5) only. SPAM/SRM/maxSRM/CNN: not found in text.
- Table IV (OCR plus image check, p5), rows per rate: LSBM, MKGM[7], 2GA[17], MOLSBM. Examples at 0.3 bpp ker1: LSBM 0.1522, MKGM 0.0867, 2GA 0.0856, MOLSBM 0.0112; at 0.8 bpp CNGL 2GA 0.1262 beats MOLSBM 0.1980. No row for "same operator, random seed/random path with matched modification count". LSBM row is the plain baseline; no definition of whether its path is random. 
- Metric: text says "Detection accuracy is indicated by the area under the ROC curve (AUC), where a curve closer to the diagonal signifies better security" (p5). Values like 0.0092 are far below 0.5, so this is not a raw AUC. A normalised area (area between ROC and diagonal) is the likely meaning; the IST paper does not state the normalisation. (The 2GA paper p12 says the area is "normalised", tr.; see below.) Value 0.5 raw would be chance; here 0 = chance.
- Seeds / repeats / CIs / train-test sizes: not found in text. The classical attacks here are threshold detectors with no stated training set.
- Also in paper: "MKGM reduced the likelihood of detection ... its image quality remained similar to standard LSBM" (p2).

## 2. GLSBM:MKGM.pdf = ISeCure 18(1), Jan 2026 (journal extension of MOLSBM)
- Title: "Enhancement of LSB Matching Steganography using Multiobjective Optimization Embedding to Improve Security and Imperceptibility". Author: Vajiheh Sabeti (sole). Venue: ISC Int'l J. Information Security (ISeCure) 18(1), pp. 1-17, Jan 2026. Received 10 Sep 2024, accepted 10 Sep 2025, online 17 Sep 2025. DOI printed (p1) as 10.22042/isecure.2025.477842.1172 (broken across lines in extraction). 17 pages. The file name "GLSBM:MKGM" is misleading: it is the MOLSBM journal version, not the GLSBM/MKGM paper.
- Optimiser/selects/objectives: same NSGA-II, 8-bit per-block seed + +/-1 pattern; F1 mismatches = modification count (p6 "minimize the pixel change rate"), F2 histogram difference (p7). Key now embedded in the image itself (p9), so reported numbers changed from IST version (e.g. Table 7 MOLSBM ker1 0.0114 vs IST 0.0112).
- Strongest sentence for our adversary reading (p5): "an optimal key is adaptively selected for each specific cover image" and the key "significantly improves security" (claimed, not tested against a random key). Also p12: "lowering these two objective functions ensures that the features of the stego and cover images remain more comparable".
- Data: NRCS; 1,000 random test images; 200 images for quality/objective plots (Fig 10, 11, p10, p12); 500 images for Table 7; 1,000 for Table 8 (p12-13). Quality tests also on Lena, Baboon, Peppers, Boat.
- Table 7 (p13): ker1/ker2/CNGL/ALE at 0.3/0.5/0.8 bpp; rows LSBM, LCG[38], MKGM, 2GA, MOLSBM. Same "AUC" wording, values 0.0114 etc (below 0.5; not raw AUC). LCG is LSBF (a different operator) with blanks at 0.8. No random-seed same-operator row.
- Table 8 (p14): "universal steganalysis": SPAM (686 features), SRM (34,671), maxSRM, maxSRMd2, "Ensemble classifier", NRCS 1,000 images, rates 0.05, 0.1, 0.2, 0.25, 0.3 bpp, columns AUC and test error. Table has NO method column and NO baseline row: only the proposed method (text: "tested the security of MOLSBM", p12). Values: SPAM AUC 0.5378 (0.05 bpp) to 0.7603 (0.3 bpp), test error 0.4725 to 0.3390; SRM 0.5678 to 0.7663 (0.3118); maxSRM 0.7435; maxSRMd2 0.7421. Here AUC is raw (>=0.5), a different definition from Table 7 under the same word. Quote (p13): "the proposed method is quite secure at low embedding rates but demonstrates diminished security as embedding rates rise." Train/test split, number of folds, seeds, CIs, subject structure: not found in text. No LSBM/random-key row, so gain from GA not isolated; no CNN steganalyser; no maxSRM baseline. So Table 8 shows the GA-optimised method is detectable at 0.3 bpp (AUC ~0.76) and gives no evidence of a detectability gain from selection.
- Table 4 (p12, PSNR at 0.3 bpp: LSBM 56.37, MOLSBM 57.66) shows the modification count falls (PSNR rise), i.e. the mechanism is fewer changes. Fig 11 (p13) plots mismatch/HistDif for LSBM vs MOLSBM on 200 images.
- Seeds/CIs/repetitions: none; single run per image set. Metric tables are means with no spread.

## 3. MKGM.pdf (Persian, SID archive copy)
- Identity (from header, p2, and from ISeCure ref [17]): V. Sabeti, S. Faiazi, H. Shirinkhah, "Improving security of LSBM steganography using genetic algorithm, multi-key and blocking" (Persian title: header p2), Iranian J. of Electrical and Computer Engineering, Part B Computer Engineering, vol 18 no 1, Spring 1399 (2020), p. 49 onward (12 PDF pages: 1 and 12 are SID ads; paper pp. 2-11). Hosted at sid.ir/paper/228423/en. DOI: not found in text. English abstract: not found (abstract is Persian; English only in the reference list). So MKGM.pdf is NOT image-only (round 6 said "no extractable text": incorrect, it has a Persian text layer; it is image-ad pages 1 and 12 only).
- Method: GLSBM = LSBM where GA chooses +1/-1 for each mismatching pixel to minimise block histogram difference; MKGM(n, m) = n keys (seeds of rand) x blocks of size m: runs GLSBM per key and "the best key" (lowest histogram difference) is kept per block (pp. 4-7, 10). MKGM(1,*) = a single key, no block division (p7). Objective: histogram difference only; not modification count. Genetic parameters popN 20, crossP 0.7, mutP 0.1, epoch 20 (p7).
- Data: NRCS; 200 images for PSNR/SSIM (Table 3, p8); 500 images for security (p8). Samples Lena, Baboon, Peppers.
- Steganalysers: ker1, ker2, CNGL, ALE only. "Table 5" (p9, labelled Table 5 though in Fig. 8-9 context) at 0.3/0.5/0.8 bpp: LSBM, LCG, MKGM(1,*), MKGM(4,16). Image-verified rows at 0.5 bpp: MKGM(1,*) ker1 0.2834, ker2 0.1349, CNGL 0.2104, ALE 0.4038; MKGM(4,16) 0.1587, 0.0748, 0.1052, 0.2999; LSBM 0.2923, 0.1443, 0.1445, 0.4099. So the single-key GA version is NOT clearly better than LSBM (CNGL 0.2104 vs 0.1445 worse); the multi-key version (best of n=4 keys per block) is better. This is the only paper with a "one key vs n keys, same operator" comparison, but it compares n selected keys against one key, not against a random key with matched modifications, and the single baseline is not randomised over keys.
- Metric text (p8, tr.): AUC is the area between the ROC curve and the diagonal, normalised; "the closer to zero, the less successful the attack". So values below 0.5 are by construction a normalised area. This clarifies the AUC reading used by the IST/ISeCure tables.
- Key quote on multi-key idea (p9, tr.): keys "are usually chosen beforehand without any criterion; but different keys produce stego images with different statistical changes."  Blocking quote (p10, tr.): local dependence in the image makes smaller search spaces better.
- SPAM/SRM/CNN: not found in text. Seeds/CIs: not found. Sizes of train/test: not found.

## 4. 2GA (JSCIT 9(4), 2021)
- Title: "Secure Image Steganography with High Visual Image Quality Based on LSBM and Genetic Algorithm". Authors: Vajiheh Sabeti, Sepideh Faiazi. Venue: J. Soft Computing and Information Technology (Babol Noshirvani Univ. of Technology), vol 9 no 4, Winter 2021 (1399), pp. 70-82. Received 12/10/2019, accepted 24/11/2020 (p1). DOI: not found in text. English abstract (p1, readable). Body Persian (pp. 3-13; tables and figure labels partly English; Persian prose was read through the garbled text layer; fine-grained prose not exhaustively verified).
- Method: two GA steps per block: (1) GA over LCG parameters (x0, a, c) that fixes the embedding pixel sequence with most LSB matches (objective Match-No, i.e. fewer modifications); (2) GLSBM as above (histogram difference). So selects the path (LCG parameters) and direction pattern. Abstract (p1): "selected the best embedding sequence for each block using the genetic algorithm and the Linear Congruential Generator (LCG)".
- Data: NRCS; 250 images (PSNR average) and 500 images (security) (pp. 11-12); Lena, Baboon, Peppers, Boat. Block size 8x8/16x16.
- Steganalysers: ker1, ker2, CNGL, ALE; Table 6 (p12) at 0.3 and 0.5 bpp; rows LSBM, LCG, GLSBM, MKGM, 2GA-LSBM. SPAM/SRM/CNN: not found.
- Key statement (p12, tr.): "GLSBM alone gives results similar to, and in a few cases worse than, LSBM; but MKGM and 2GA-LSBM have higher security than LSBM." Example 0.5 bpp: LSBM ker1 0.2923; GLSBM 0.2834; MKGM 0.1587; 2GA 0.2076.
- Metric: AUC normalised (p12, tr.), closer to 0 means attack less successful.
- Seeds/CIs: not found. Several numbers differ across the three versions of the same experiment (GLSBM 0.5 bpp CNGL: 0.1096 in 2GA Table 6 vs 0.2104 in MKGM table; MKGM(4,16) 0.5 bpp CNGL 0.1052 vs 0.1252, ALE 0.2999 vs 0.3055; 2GA ker1 0.3 bpp 0.0856 in IST/2GA vs 0.0860 in ISeCure). Values are not reproducible across versions; no seed/spread given.

## 6. Adversarial paragraph
(a) GA vs random key. Strongest case for pre-emption: the series (MKGM 2020, 2GA 2021, MOLSBM 2024, ISeCure 2026) is entirely a comparison of GA-selected seeds/paths with a non-selected baseline, and MKGM p9 even contrasts n selected keys with one key (MKGM(1,*)); the ISeCure text (p5) argues that "an optimal key is adaptively selected". But none has a random key under the same operator with equal pair/modification counts: the baseline is LSBM (an unoptimised path, modification count not controlled) or other schemes. The GA gain they report is confounded by fewer modifications (F1 and Match-No are literally modification counts; PSNR rises 56.37 to 57.66 at 0.3 bpp, ISeCure Table 4 p12). So (a) is not pre-empted for the controlled version, but our wording must not claim that nobody compared GA selection with non-GA selection.
(b) "No detectability gain". They claim a gain, using ker1/ker2/CNGL/ALE (threshold-type attacks for LSBM, which are driven by change count and histogram shape) and normalised "AUC" values below 0.5. Table 8 (SPAM/SRM/maxSRM/maxSRMd2, ensemble) reports only the proposed method, shows AUC up to 0.76 at 0.3 bpp, and gives no baseline, so it neither supports nor contradicts a null gain. MKGM p9 and 2GA p12 also report that GLSBM (single key) is "similar or worse" than LSBM, consistent with, not against, a null for the direction GA. Risk: a reviewer can say the claim "GA brings no gain" is contradicted by Tables IV/7; our answer must be that those detectors respond to modification count, which matched controls hold fixed.
(c) Texture-guided keys. Not covered in Group C: none uses texture or edge measures in the key objective (F2 is histogram difference); related only through the generic "edge-based embedding [12]" citations. Luo et al. is absent from Paper/. Their NRCS natural images, no subject splits, no medical data.
